System overview

readme

I came to design from computer engineering — which mostly means I want to know how something works before I redesign it. Turns out that's a research habit in disguise.

Across an agency and a bench of freelance clients, the method holds: talk to real users, isolate the friction, ship the smallest change that moves the metric, then watch the numbers after launch. Solve the problem first; earn the delight second — because humans remember delight.

Curious generalist: field research, usability testing, web & mobile apps, brand, print. Currently re-learning to code so I can build the ideas, not just draw them. And no — I don't "synergize aesthetics and functionality." I hate jargon. I make hard things easy.
